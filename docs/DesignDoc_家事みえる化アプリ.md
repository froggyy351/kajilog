## 全体アーキテクチャ

- **フロントエンド**: Vite + ReactによるPWA。`vite-plugin-pwa`でmanifest・service workerを構成する
- **バックエンド**: Python(FastAPI)。VercelのPythonサーバーレス関数としてFastAPIアプリ全体を1つの関数でホストする
- **ホスティング**: Vercelに統一（フロント・バックエンドとも同一プロジェクトで完結）。懸念点はコールドスタート時の遅延（オープンクエスチョン参照）
- **DB**: Supabase(Postgres)。FastAPIから`SQLAlchemy`または`asyncpg`で接続する
- **NFCタグ**: NDEFのURIレコードとしてURLを書き込み、専用アプリ（NFC Tools等）で開発者側が事前に書き込む
- **記録の主体分離**: 「どの家事か」はタグが持つ／「誰がやったか」は端末（ブラウザ）が覚える、という役割分担にする（詳細は次項）

---

## NFCタップ記録フロー（方法B 詳細）

1. **事前準備**: 家事の実行場所ごとに1枚NFCタグを設置。タグには `https://{domain}/t/{tagId}` という固定URLを書き込む。
   - `tagId` は家事名を直接埋め込まない間接参照にする。あとから家事名・重みを変更してもタグの物理的な書き直しが不要になるため。
2. **タップ**: iPhoneでタグに触れる → iOS標準の「このWebサイトを開きますか」バナーが表示 → タップして開く。
3. サーバーが `tagId` から紐づく家事情報（名前・重み・世帯）を引く。
4. **誰がタップしたかの判定**:
   - 初回のみ「健太／美咲」の2択ボタンを表示し、選択結果をその端末のlocalStorage（またはcookie）に保存する。
   - 2回目以降は保存済みの人物として自動記録し、確認画面だけを一瞬表示する。
5. 記録確定後、「✅ トイレ掃除を記録しました（健太）」のようなフィードバック画面を表示。
6. **取り消し導線**: 記録直後の画面に「取り消す」ボタンを設置（誤タップ・誤認識対応。既存CAJICOの取り消しモーダルに相当する体験をWeb上で再現）。

## データモデル

`backend/models.py`にSQLAlchemyモデルとして実装済み（ローカルは`backend/database.py`経由でSQLite、`DATABASE_URL`環境変数でSupabase(Postgres)に切り替え可能）。`backend/seed.py`でテーブル作成とサンプルデータ投入ができる（`uv run python seed.py`）。IDは全テーブルUUID文字列（tagIdが推測困難な値になるようにするため）。

- **household**（世帯）: id, name
- **member**（世帯メンバー）: id, household_id, name, icon, color
- **chore**（家事マスタ）: id, household_id, name, weight, location
- **tag**（物理タグ）: id, chore_id, created_at
- **record**（実績記録）: id, chore_id, member_id, recorded_at, weight_snapshot, undone_at (nullable)

`weight_snapshot` を持たせているのは、家事の重みを後から変更しても過去の実績集計が遡って変わらないようにするため（オープンクエスチョンにも関連）。

## オープンクエスチョン / 未決事項

- `vercel.json`の`builds`/`routes`構成が実際のVercelデプロイで想定通り動くかの検証（ローカルではフロント・バックエンドそれぞれ単体動作のみ確認済み）
- PWAのアイコン画像（192x192/512x512）が未作成。`vite.config.js`のmanifestは参照パスのみ設定済み
- Vercelのコールドスタートが体感的に遅い場合、Render等の常時稼働ホスティングへの移行を検討する（実際に使ってみてから判断）
- 同じ家事を同時に2人がタップした場合の扱い（二重記録として許容するか、警告を出すか）
- 「誰がタップしたか」を端末に記憶する方式の永続性（機種変更時の再設定、ブラウザのデータ削除で消える点への対処）
- タグの物理選定（水回り設置のための耐水性・耐久性）と購入先
- 家事名・重みを変更した際、過去実績をどこまで遡って再計算するか（上記`weight_snapshot`案で足りるか）
